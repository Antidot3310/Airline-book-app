# Авиакасса — Настольная система бронирования и продажи авиабилетов

[![.NET 10](https://img.shields.io/badge/.NET-10.0-512BD4?logo=dotnet)](https://dotnet.microsoft.com/)
[![WPF](https://img.shields.io/badge/UI-WPF%20Desktop-0078D7?logo=windows)](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/)
[![SQLite](https://img.shields.io/badge/Database-SQLite%20(EF%20Core%2010)-003B57?logo=sqlite)](https://www.sqlite.org/)
[![MVVM](https://img.shields.io/badge/Pattern-MVVM%20(CommunityToolkit)-009688)](https://learn.microsoft.com/dotnet/communitytoolkit/mvvm/)
[![Tests](https://img.shields.io/badge/Tests-135%20Passed-brightgreen)](backend/tests/AirlineTicketOffice.Core.Tests/)

Современное автономное настольное приложение (Windows Desktop) на платформе C# (.NET 10, WPF) для комплексной автоматизации продажи, бронирования, оплаты, возврата авиабилетов и аналитики авиакомпании.

Разработано в рамках 42 инкрементов (11 фаз дорожной карты) в строгом соответствии с модульной архитектурой и принципом **Zero Code-Behind**.

---

## 🚀 Быстрый старт

### Системные требования
* **ОС**: Windows 10 / 11 (для запуска графического интерфейса WPF). Сборка и тестирование ядра (`Core`) поддерживаются кроссплатформенно на Linux / macOS / Windows.
* **Платформа**: [.NET 10 SDK](https://dotnet.microsoft.com/download/dotnet/10.0) (версия 10.0.100 или новее).
* **СУБД**: Встроенная SQLite (не требует внешней установки, файл `airline.db` генерируется автоматически при первом запуске).

### Сборка решения
```bash
# Восстановление зависимостей и чистая сборка решения в Release-режиме
dotnet clean
dotnet build AirlineTicketOffice.sln -c Release
```

### Запуск полного набора автоматических тестов (135 тестов)
```bash
dotnet test AirlineTicketOffice.sln -c Release
```

### Запуск сквозного интеграционного теста приёмки (DoD 10 шагов)
```bash
dotnet test backend/tests/AirlineTicketOffice.Core.Tests/ -c Release --filter FullyQualifiedName~EndToEndDemoScenarioTests
```

### Запуск графического приложения
```bash
dotnet run --project frontend/src/AirlineTicketOffice.Wpf/AirlineTicketOffice.Wpf.csproj -c Release
```

## 🏛 Архитектура системы

Решение построено по многоуровневой модульной архитектуре с полным разделением ответственности:

```text
fullstack-monorepo/
├── backend/
│   ├── src/AirlineTicketOffice.Core/          # Ядро бизнес-логики (M1–M15)
│   │   ├── Common/                            # Result / Result<T> паттерн
│   │   ├── Contracts/                         # Типизированные DTO и интерфейсы M1–M15
│   │   ├── Data/                              # AirlineDbContext (EF Core 10), DbInitializer
│   │   ├── Domain/Entities/                   # 13 сущностей доменной модели
│   │   ├── Domain/Enums/                      # 12 строго типизированных перечислений
│   │   ├── Extensions/                        # Регистрация AddAirlineCore(), миграции
│   │   └── Services/                          # Реализации сервисов M1–M15
│   └── tests/AirlineTicketOffice.Core.Tests/  # 135 модульных и интеграционных тестов
│       ├── Common/, Data/, Services/          # Модульные тесты M1–M15
│       └── Integration/                       # CoreIntegrationTests, EndToEndDemoScenarioTests
├── frontend/
│   └── src/AirlineTicketOffice.Wpf/           # Десктоп-клиент (WPF, .NET 10-windows)
│       ├── Converters/                        # Value-конвертеры для XAML
│       ├── Services/                          # INavigationService, NavigationService
│       ├── ViewModels/                        # 16 моделей представления (CommunityToolkit.Mvvm)
│       ├── Views/                             # 16 представлений и диалогов (Zero Code-Behind)
│       ├── App.xaml / App.xaml.cs             # Точка входа, DI-контейнер
│       └── MainWindow.xaml / .xaml.cs         # Главный рабочий каркас приложения
└── docs/                                      # Полный пакет технической документации (11 файлов)
```

### Ключевые архитектурные принципы
1. **Изоляция представления:** Проект `AirlineTicketOffice.Wpf` общается с ядром исключительно через типизированные контракты `AirlineTicketOffice.Core.Contracts.*`. Представления не имеют прямого доступа к `AirlineDbContext` или сырому SQL.
2. **Zero Code-Behind:** Все файлы `*.xaml.cs` содержат только вызов `InitializeComponent()`. Вся интерактивная логика, валидация, команды и навигация инкапсулированы в ViewModels.
3. **Единый источник времени (`IVirtualClockService` M12):** Ни один компонент не использует системный `DateTime.Now` для бизнес-логики. Все временные расчёты опираются на виртуальные часы с поддержкой ускорения, сдвига времени и автоматического срабатывания регламентных задач.
4. **Отказоустойчивость и предсказуемость:** Бизнес-методы ядра возвращают объекты `Result` / `Result<T>` вместо неконтролируемого выбрасывания исключений.
5. **Неизменяемый аудит (`IAuditLogService` M11):** Все ключевые бизнес-события (создание рейса, бронирование, оплата, возврат, аннулирование) фиксируются в журнале аудита с фиксацией роли, времени и описания.

## 👥 Ролевая модель и функциональные модули

Система поддерживает 3 роли пользователей и сервисную подсистему «Эмулятор»:

| Роль / Модуль | Экраны | Ключевые возможности |
|---|---|---|
| **Выбор роли** | `W-01` | Быстрое переключение между ролями и запуск пульта эмулятора |
| **Пассажир** | `W-02` `W-03` `W-04` `W-05` `W-06` `W-07` `W-10` | Поиск рейсов, интерактивная схема салона (SSJ-100, A320, B737, B777, A350), 15-минутный холд мест, ввод данных пассажиров, переключатель багажа (+1 500 ₽), оплата картой с таймером обратного отсчёта, просмотр электронных билетов, печать маршрутных квитанций, добровольный онлайн-возврат |
| **Кассир** | `W-02` `W-08` `W-09` `W-10` | Рабочее место кассира: поиск/создание клиента, быстрая продажа билетов, оплата наличными с автоматическим расчётом сдачи, оформление возвратов при личном обращении по шкале штрафов (90% / 50%), печать кассовых чеков и квитанций возврата |
| **Администратор** | `W-02` `W-11` `W-12` `W-13` `W-14` `W-15` `W-10` | Справочники аэропортов, флота ВС (перевод на ТО) и типов судов; создание рейсов, смена борта (TC-09/10), отмена рейса с каскадным 100% возвратом (TC-08); настройка базовых тарифов и багажа; 4 аналитических отчёта (загрузка, выручка, каналы, статистика возвратов); журнал аудита (только чтение) |
| **Эмулятор** | `W-16` | Служебный пульт управления виртуальным временем (+15 мин, +1 час, +1 день), переключение режимов платёжного шлюза (Успех, Отказ, Таймаут, Случайный), ручное подтверждение зависших транзакций (TC-15), принудительный запуск регламентных задач |

## 🎬 Эталонный 10-шаговый сценарий приёмки (Definition of Done)

Работоспособность системы на 100% подтверждается сквозным сценарием (автоматизирован в `EndToEndDemoScenarioTests`):

1. **Шаг 1 (Администратор)**: Вход под ролью Администратора, создание рейса `SU-101` SVO $\rightarrow$ AER, установка тарифа, генерация схемы мест.
2. **Шаг 2 (Пассажир)**: Поиск рейса, выбор и бронь места `1A` с багажом (фиксация 15-минутного таймера).
3. **Шаг 3 (Кассир)**: Попытка забронировать место `1A` (блокировка двойной продажи), продажа места `1C` за наличные со сдачей 500 ₽ и печатью чека.
4. **Шаг 4 (Эмулятор)**: Сдвиг виртуального времени на 16 минут вперёд $\rightarrow$ автоматическое снятие просроченной брони Пассажира и освобождение места `1A`.
5. **Шаг 5 (Пассажир)**: Повторное бронирование `1A`, эмуляция отказа шлюза (`AlwaysFail`), затем успешная оплата картой (`AlwaysSuccess`) и печать билета.
6. **Шаг 6 (Пассажир)**: Добровольный возврат билета `1A` за 24+ часа до вылета $\rightarrow$ расчёт и выплата ровно **90%** стоимости, печать квитанции возврата.
7. **Шаг 7 (Эмулятор)**: Сдвиг времени на момент за 10 часов до вылета рейса ($<24$ ч).
8. **Шаг 8 (Кассир)**: Оформление возврата билета `1C` в кассе $\rightarrow$ расчёт и выплата ровно **50%** стоимости, печать квитанции возврата.
9. **Шаг 9 (Администратор)**: Покупка нового билета `2A`, отмена рейса администратором $\rightarrow$ каскадный массовый возврат **100%** стоимости всем пассажирам и блокировка мест.
10. **Шаг 10 (Администратор)**: Формирование всех 4 аналитических отчётов и проверка хронологической полноты записей журнала аудита.
